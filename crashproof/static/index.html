PUT RELIABILITY ON DISPLAY

Five ways to test the promise.

Each scenario is backed by actual workflow execution and visible business-state changes.

01

Retry safely

Fail a payment attempt once. Temporal schedules another attempt; the workflow completes.

02

Compensate

Reject fulfillment after payment. The Saga refunds the charge and releases inventory.

03

Crash & resume

Exit a dedicated worker at the commit boundary. Restart it and inspect the deduplicated charge.

04

Replay a request

Submit the same idempotency key and payload again. The API returns the existing order.

05

Wait for approval

Pause the durable workflow before payment, then send an approval or rejection signal.
